A full review of the repository on 19 October 2026: what was checked, the scores, what was fixed and what is still
open. Open items are tracked in [ROADMAP.md](ROADMAP.md).

- All application modules, templates, tests, the Dockerfile, Compose file and documentation were read.

## Findings and status

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | High | Pinned dependencies about 21 months old, with 150 known vulnerabilities. Relevant because the service parses untrusted PDFs | **Fixed.** All packages updated to current releases. `pip-audit` on the production image now finds none |
| 2 | High | No version control | **Fixed.** Git repository created and pushed to a private GitHub repository |
| 3 | Medium | `upload` and `review_submit` are `async` routes that did blocking PDF work on the event loop, freezing every other request (including status polling) for seconds | **Fixed.** The blocking work runs in a worker thread (`run_in_threadpool`) |
| 4 | Medium | The upload size limit only applies after Starlette has spooled the whole request to temporary disk | Open. Enforce at the reverse proxy ([ROADMAP.md](ROADMAP.md#3-protect-the-server-from-hostile-uploads-review)) |
| 5 | Medium | No limit on page dimensions, so a crafted PDF can exhaust memory when rendered | Open ([ROADMAP.md](ROADMAP.md#3-protect-the-server-from-hostile-uploads-review)) |
| 6 | Medium | Answers from the AI fallback were marked certain, so they skipped the review screen and could change the score silently | **Fixed.** They are flagged "Tick read by AI as X: please confirm". The AI answer is still used for scoring |
| 7 | Low | Review form fields with out-of-range question numbers caused a server error (`match_999`) or stored bad data (`answer_0` reached the last question through negative indexing) | **Fixed.** Fields outside 1..n are ignored |
| 8 | Low | Summary counts overlap (`chose_e` with `key_unknown`, `unanswered` with `wrong`) | Open ([ROADMAP.md](ROADMAP.md#6-smaller-fixes-review)) |
| 9 | Low | Container ran as root, with no health check in the image itself | **Fixed.** Runs as user `app` (uid 10001), with a `HEALTHCHECK` |
| 10 | Low | No timeout on the Claude API call | Open ([ROADMAP.md](ROADMAP.md#6-smaller-fixes-review)) |
| 11 | Low | Text inside Form XObjects is not filtered from the reordered PDF | Open ([ROADMAP.md](ROADMAP.md#6-smaller-fixes-review)) |
| 12 | Low | pypdf 6 deprecation: merging into a page not attached to the writer, which pypdf 7 will reject | **Fixed.** Pages are added to the writer before merging |

Also noted as strengths worth keeping: privacy-conscious logging, unguessable job tokens with automatic deletion, a
review swap that keeps the mapping one-to-one (consistent between the page script and the server), a tick decision
that defers to a person when its signals disagree, and a reordered PDF that stays vector and searchable.

## Upgrading an existing deployment

The image now runs as a non-root user. A named volume created by an earlier image holds files owned by root, which
the new user cannot write. Either remove the volume (its jobs expire within `RETENTION_HOURS` anyway) or change the
owner once:

```sh
docker run --rm -u root -v exam-data:/data exam-answer-checker chown -R app:app /data
```
